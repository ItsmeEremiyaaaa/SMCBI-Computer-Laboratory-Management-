# ComLab 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Laravel lab reservation system as a React SPA on Vercel with Supabase, a full dashboard redesign, and live per-PC 3D lab monitoring.

**Architecture:** Vite React SPA. All data access goes through one module `src/lib/api.ts` with two backends: `mock` (in-memory + localStorage, seeded) used when `VITE_SUPABASE_URL` is unset, and `supabase` otherwise. Pure rules (seat status, overlap, validation) live in `src/lib/` and are unit-tested; the database re-enforces the security-relevant ones (RLS, overlap trigger).

**Tech Stack:** Vite 7, React 19, TypeScript, Tailwind v4, react-router-dom 7, three + @react-three/fiber 9 + @react-three/drei 10, @supabase/supabase-js 2, lucide-react, vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-comlab-3d-design.md`

## Global Constraints
- Labs: "Computer Laboratory 1", "Computer Laboratory 2", "Computer Laboratory Netlab"; each 30 PCs, 5 rows × 6 cols, labels `PC-01`…`PC-30`.
- Roles: `admin | staff | teacher`. Sign-up creates `teacher`, `approved=false`. Sign-up email must end with `@smcbi.edu.ph`.
- Departments: `BSIT, BSBA, BSHM, BEED, BSED` (+ `Admin` for staff). Year levels: `1st Year`…`5th Year`.
- PC manual status: `free | in_use | broken`. Shown status adds `reserved`.
- Reservation status: `pending | approved | rejected | completed`. Event type: `academic | personal | holiday | meeting`.
- Validation: date ≥ today, end > start (HH:MM), participants ≥ 1 if given.
- Time zone for "now" and "today": `Asia/Manila`.
- 3D: primitives/instancing only, no model files. Vercel Hobby + Supabase Free only.
- Every route except `/login`, `/signup` requires an approved profile.

## Review Focus
1. Whole-lab reservation vs PC reservation in the same slot → must conflict both ways (Task 1 test, Task 7 SQL test).
2. Two admins approving overlapping requests at once → second approval fails in the DB (Task 7 trigger test).
3. Unapproved teacher signs in → sees only "Awaiting approval"; DB rejects their writes (Task 3 route test, Task 7 RLS test).
4. "Now" near midnight / browser not in Manila time → seat status uses Asia/Manila (Task 1 test).
5. No WebGL (old laptop, some phones) → 2D seat grid fallback with the same colors and click behavior (Task 4 test).

### Task 7: Supabase schema, RLS, conflict trigger

**Files:** Create `supabase/migrations/0001_init.sql`, `supabase/seed.sql`, `supabase/tests/policies.sql`.

- Tables/enums exactly as spec "Data". `profiles` auto-created by trigger on `auth.users` insert from `raw_user_meta_data` (role `teacher`, approved false); reject non-`@smcbi.edu.ph` emails in that trigger.
- Helpers: `is_approved()`, `has_role(r text[])` as `security definer` reading `profiles` for `auth.uid()`.
- RLS: read all core tables if `is_approved()`; `pcs` update by admin/staff; `reservations` insert by approved users as themselves with status `pending`; update status only by admin; delete own pending; `students`, `labs` write admin; `events` write owner or admin; `profiles` update own details (not role/approved) or admin any.
- Trigger `before update on reservations` when new.status='approved': raise `'conflict'` if any other approved row overlaps (same date, times overlap, same lab and (either pc_id null or pc_ids equal)); take `pg_advisory_xact_lock(hashtext(lab_id::text||date))` first so concurrent approvals serialize.
- Add `pcs` and `reservations` to `supabase_realtime` publication.
- Seed: 3 labs, 90 PCs.
